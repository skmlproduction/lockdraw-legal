This policy describes how LockDraw (“we”, “us”) processes information when you use the Android app. It applies to local drawing, optional collaborative rooms (data on your operator’s server), optional Sign in with Google, optional Google Play tips, on-device widget / overlay previews, and optional Firebase diagnostics / analytics when enabled in the build.

2. Who operates the server

Collaborative rooms sync to an API base URL configured at app build time (lockdraw.api.base.url → your deployment). You (the operator hosting that API) are the data controller for data stored or processed on that server. The app is a client; we do not provide a default public multi-tenant cloud for all users unless you deploy one and disclose its URL.

Document for users in the store listing: who runs the server and this privacy policy URL.

3. Data we process

3.1 On your device (all users)

  • Onboarding flag — whether the welcome flow was completed (lockdraw_onboarding).
  • Display name — last name entered on the home screen for convenience (lockdraw_user_prefs). Used locally; in room mode the same value is sent to the server when you create or join a room.
  • Drawing preview — PNG preview for widget and optional overlay (filesDir), not uploaded by default.
  • Canvas preferences — e.g. background colour (local preferences).

3.2 Collaborative room mode (when enabled)

Sent to your operator’s server over HTTPS (REST) and WSS (WebSocket):

  • Display name on the canvas (pseudonym; may be “Guest” if empty).
  • Room join code and room identifier.
  • Drawing data — stroke batches and sticker metadata (coordinates normalised 0–1, colours, sequence numbers for sync).
  • Session credentials — access token and WebSocket URL returned by the server; optionally stored on device only if you turn on “Save session on this device” (encrypted preferences, or plain fallback if encryption fails).
  • Participant identifier — UUID assigned by the server for the room session.
  • Offline queue (optional) — if session save is enabled, unsent stroke batches may be stored on device until reconnect.

We do not collect precise location, contacts, photos library, or microphone through LockDraw for room sync.

3.3 Google Sign-In (optional, when enabled at build time)

  • On device: a display label (name or email from the token) and Google subject id in app preferences (lockdraw_google_account).
  • Google ID token is kept in RAM only until you sign out; it is not written to disk.
  • If you create or join a room while signed in, the app may send the ID token once to your server so the server can verify it (when LOCKDRAW_GOOGLE_WEB_CLIENT_ID is configured) and stabilise participant identity via Google sub.

Google processes sign-in under Google Privacy Policy.

3.4 Google Play purchases (optional)

Tips on the Support screen are processed by Google Play Billing. We receive product catalog and purchase state through Google’s APIs; we do not store card numbers. Google’s policies apply to payment data.

3.5 Technical data on the server (operator responsibility)

When you host the LockDraw API (:server or equivalent), typical technical logs may include:

  • HTTP/WebSocket access logs (IP address, timestamps, request paths, response codes).
  • Room and session identifiers in application logs for operations and security.
  • Error and security events (invalid tokens, rate limits).

The reference server in the open-source repo holds room data in memory by default (no long-term stroke archive unless you add persistence). Configure retention, backups, and log rotation on your infrastructure and document them here or in a server addendum.

3.6 Firebase Crashlytics and Analytics (when google-services.json is present)

Builds that include Firebase may send:

  • Crashlytics — crash stack traces and diagnostic metadata to Google to improve stability. There is no separate in-app “off” switch beyond uninstalling or clearing app data; disclosed here and in Play Data safety.
  • Analytics — only after you turn on the optional “usage data” / analytics toggle in Settings (default off). Events are coarse (for example app open, drawing started, drawing saved, widget added, support purchase). Revoking the toggle stops further analytics collection.

Google processes this data under Google Privacy Policy and Firebase terms. If Firebase is not configured in a build, these SDKs are not active.

7. Security

  • Production API must use TLS (HTTPS / WSS) only; see BROKER_AND_TRANSPORT_SECURITY.md.
  • Room access requires a session token; clients cannot subscribe to arbitrary rooms without it.
  • Optional encrypted storage for saved sessions on device.

No method is 100% secure; report issues to *[security contact]*.

8. Your rights

Depending on your region (GDPR, UK GDPR, etc.), you may have the right to:

  • Access data we hold about you on the server (strokes in active rooms, session metadata, logs tied to your token).
  • Rectify inaccurate display names (change in app before or during a session).
  • Erase data — see §9.
  • Restrict or object to certain processing.
  • Portability — export drawings locally (PNG share); server-side export only if the operator provides it.
  • Complain to your supervisory authority.

Contact: *[privacy@yourdomain.com]* — we respond within *[30]* days where required.

9. Deletion and account

LockDraw has no mandatory cloud account. Deletion options:

1. Local — uninstall the app or clear storage in Android settings (removes prefs, preview, optional saved session). 2. Leave a room — stop syncing; server copy remains until operator deletes the room or restarts in-memory storage. 3. Request server deletion — email *[privacy@yourdomain.com]* with room code / approximate time / display name used; operator deletes room data and associated logs where identifiable. 4. Google Sign-In — use “Sign out” in Settings; clears on-device label; server may retain prior participantId mapping until room data is deleted.

We will confirm deletion when practicable. Purchases remain in Google Play history (managed by Google).

10. Children

LockDraw is not directed at children under 13 (or minimum age in your country). Room mode allows user-generated drawings shared in real time; parents should supervise minors. If you believe a child provided data, contact us for deletion.

11. International transfers

If the server is outside your country (e.g. EU user, US server), transfers rely on appropriate safeguards (SCCs, adequacy, or your documented basis). State server location in the store listing.
